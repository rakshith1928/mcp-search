# Omnisearch v1.1 — New Providers & Parallel Search (Design)

Date: 2026-09-02
Status: Approved (design dialogue 2026-09-02)
Branch: `feat/v1.1-providers` (to fork from `main` @ a0ae41a)

## Context

Omnisearch v1 (merged to `main` @ a0ae41a) ships four providers (Brave,
Anthropic, OpenAI, Moonshot), a lazy registry, LRU+TTL cache, token-bucket
rate limiting, a fallback-chain router, an MCP server, a CLI, and native
OpenCode/Kilocode plugins. The original plan explicitly deferred Tavily,
Google, SearXNG, and Perplexity to v1.1, and marked parallel execution
"(Optional)". This spec covers exactly that deferred scope:

1. Four new providers: **Tavily**, **Google Programmable Search**,
   **SearXNG**, **Perplexity**.
2. **Parallel multi-provider search** with result merging, exposed as an
   opt-in `parallel` argument on the existing `omnisearch` tool (plus
   `--parallel` on the CLI and the same arg through the plugins).

User decisions from the design dialogue:

- Scope = the plan's v1.1 deferrals (not broader platform work).
- Parallel search is an **opt-in argument on the existing tool**, not a
  second tool and not config-driven automatic fan-out.

## Non-goals (v2 candidates)

Per-call participant lists in the tool schema, streaming responses,
persistent on-disk cache, remote/SSE MCP transport, retry-with-backoff
distinct from rate limiting, cross-provider score-based re-ranking.

## 1. New providers

Each provider follows the v1 pattern exactly: one file in
`packages/mcp-server/src/providers/`, structural dependency injection for
tests, fail-fast credential validation at construction, mapping into
`SearchResult { title, url, snippet }` with HTML stripped from snippets,
and registration in `AVAILABLE_PROVIDERS`, `PROVIDER_LOADERS`,
`ENV_BY_PROVIDER`, and the tool schema's provider enum. `bun test` mocks
the network; no live API calls in tests.

### 1.1 Tavily — `providers/tavily.ts`

- `POST https://api.tavily.com/search`, headers
  `Authorization: Bearer <key>` + `Content-Type: application/json`.
- Body: `{ "query": <query>, "max_results": <n> }` where n = maxResults
  clamped to 1..20, default 10.
- Response mapping: `results[] → { title, url, snippet: stripHtml(content) }`.
- Non-200 → `Tavily search failed: HTTP <status> — <first 200 chars of body>`
  (same shape as the Brave provider).
- Env: `TAVILY_API_KEY` (validated at construction via `resolveApiKey`).

### 1.2 Google Programmable Search — `providers/google.ts`

- `GET https://www.googleapis.com/customsearch/v1?key=<GOOGLE_API_KEY>&cx=<GOOGLE_SEARCH_ENGINE_ID>&q=<query>&num=<n>`
  with n clamped to 1..10 (Google's per-request maximum; no pagination in
  v1.1 — a maxResults above 10 yields at most 10 results).
- Response mapping: `items[] → { title, url: link, snippet: stripHtml(snippet) }`.
- Missing `items` → `[]`.
- Env: `GOOGLE_API_KEY` (resolved by the registry through
  `ENV_BY_PROVIDER`) **and** `GOOGLE_SEARCH_ENGINE_ID` (validated by the
  factory itself via `requireEnv`, because the registry's single-key
  model cannot express two credentials).
- Non-200 → `Google search failed: HTTP <status> — <detail>`.

### 1.3 SearXNG — `providers/searxng.ts`

- `GET <SEARXNG_BASE_URL>/search?q=<query>&format=json`.
- The base URL is required configuration, not a secret:
  `ENV_BY_PROVIDER.searxng = "SEARXNG_BASE_URL"`, so the standard
  requireEnv-on-load path works unchanged. Trailing slash is normalized.
- Response mapping: `results[] → { title, url, snippet: stripHtml(content) }`.
- No API key. A 403 response produces an error hinting that the instance
  must enable the JSON format (`use_default_settings` / `formats: [html,
  json]` in SearXNG settings) — the most common misconfiguration.

### 1.4 Perplexity — `providers/perplexity.ts`

- OpenAI SDK with `baseURL: "https://api.perplexity.ai"`, model
  `sonar`, a single `chat.completions.create({ model, messages: [{ role:
  "user", content: query }] })` call — Perplexity searches automatically;
  there is no tool loop and no `thinking` parameter.
- Citation extraction, in priority order:
  1. `choices[0].message.search_results[] → { title, url }` (current API)
  2. `choices[0].message.annotations[].url_citation` (OpenAI-compatible shape)
  3. `choices[0].message.citations[]` (bare URL strings → title = url)
- maxResults applied by slicing after extraction.
- Env: `PERPLEXITY_API_KEY`. LLM-backed like Moonshot/OpenAI — documented
  as expensive in the README cost table.
- `importSdk` injection point mirrors the Moonshot provider so a missing
  SDK maps to a clear install hint.

### 1.5 Registry integration

- `AVAILABLE_PROVIDERS` order: `brave, anthropic, openai, moonshot, tavily,
  google, searxng, perplexity`. The unknown-provider error message and the
  zod enum derive from the existing constants/shape — they grow
  automatically.
- `DEFAULT_RATE_LIMITS`: tavily `15/60s`, google `10/60s` (free tier is
  100 queries/day — the conservative rate keeps bursts under quota),
  searxng `60/60s` (self-hosted), perplexity `10/60s` (LLM-backed).

## 2. Parallel search

Implemented **inside the router** so all three surfaces (MCP tool, CLI,
plugins) share one code path, one merge strategy, and consistent
cache/limiter behavior.

### 2.1 Trigger

- Tool schema gains `parallel: z.boolean().optional().describe("Fan out
  across all configured providers and merge results")`.
  `OmnisearchToolArgs.parallel?: boolean`.
- CLI gains a boolean `--parallel` flag; usage line becomes
  `Usage: omnisearch search <query> [--provider <name>] [--max <n>] [--parallel]`.
- Plugin args flow the same `parallel` boolean through
  `createPluginHooks` to the router.

### 2.2 Participant resolution

When `parallel` is set, participants (a `ProviderName[]`) resolve in
priority order:

1. `OMNISEARCH_PARALLEL` env var (comma-separated provider names,
   validated — unknown names throw with the available list, same style as
   `OMNISEARCH_PROVIDER`). Parsed by `routerConfigFromEnv` into a new
   optional `RouterConfig.parallelParticipants`, so all surfaces inherit
   it and tests can inject it directly.
2. Otherwise: every provider in `AVAILABLE_PROVIDERS` whose required env
   var is set (a non-throwing presence check helper in util.ts). Google
   counts when `GOOGLE_API_KEY` is present; its `cx` is validated at load.
3. If the resolved list is empty → fall back to ordinary single-provider
   search (no error).

If a `chain` override was also supplied, parallel mode ignores it (the
participant list supersedes it).

### 2.3 Execution

- `Router.search` signature: `search(query, options?, chain?, parallel?)`.
- Per participant, an independent async task: check the participant's own
  cache key → resolve provider → acquire that provider's limiter →
  `provider.search(query, { maxResults })`. All tasks run under
  `Promise.allSettled`.
- Each participant's results are cached under its own single-provider key,
  so a later single-provider search hits cache.

### 2.4 Merging

- Only fulfilled participants contribute, in participant order.
- Round-robin interleave that preserves each provider's internal ranking:
  first result of provider 1, first of provider 2, …, then seconds, etc.
- Dedupe by exact URL (first occurrence wins).
- Cap the merged list at `maxResults` (default 10).
- `SearchResponse` for parallel mode: `provider` = first participant
  (backward compatibility), plus new optional fields
  `mode: "parallel"`, `providers: ProviderName[]` (all participants
  attempted), `failedProviders: ProviderName[]` (rejected participants).
  Single-mode responses leave these undefined (v1 compatibility).
- The merged response is cached under a composite key
  (`parallel:<fnv(sorted participant list)>` + query + options) via a new
  `mergedCacheKey(participants, query, options)` in cache.ts. A repeated
  identical parallel call is served entirely from cache.

### 2.5 Failure handling & output

- Some providers fail → their results are excluded, `failedProviders`
  lists them, and the markdown gains one trailing note line:
  `Note: <n> provider(s) failed: <names>`.
- All participants fail → throw the existing combined
  `All search providers failed — <name>: <message> | …` error.
- Markdown: `normalizeResults` gains an optional `via` label override so
  the header reads `Query: "…" (via parallel: brave, tavily)` instead of
  a single provider name. No other format changes.

## 3. Types & surfaces summary

- `SearchResponse` (types.ts): add optional `mode?: "single" | "parallel"`,
  `providers?: ProviderName[]`, `failedProviders?: ProviderName[]`.
- `normalizeResults(query, provider, results, via?)` — 4th optional param.
- `RouterConfig`: add optional `parallelParticipants?: ProviderName[]`.
- `routerConfigFromEnv`: parse/validate `OMNISEARCH_PARALLEL`.
- Tool schema / CLI / plugin: the `parallel` passthrough described above.
- Cache: add `mergedCacheKey`.

## 4. Testing strategy (TDD throughout)

Same discipline as v1 — tests first, watched failing, then implementation:

- Per provider (`tavily/google/searxng/perplexity.test.ts`): request shape
  (URL, headers, body), response mapping incl. HTML stripping, non-200
  errors with status, credential/base-URL validation, empty-response
  handling; Perplexity citation-extraction priority order + real-client
  construction offline.
- Router parallel (`router.test.ts` new describe): participant resolution
  priority (config > env > presence-scan > fallback-to-single), fan-out
  calls every participant once, round-robin interleave order, URL dedupe,
  maxResults cap, partial failure (results + failedProviders + note line),
  all-fail throws combined error, per-participant cache isolation, merged
  cache hit (second call: zero provider calls), limiter acquired per
  participant.
- `cache.test.ts`: mergedCacheKey determinism and sensitivity.
- `normalize.test.ts`: `via` override label; failed-provider note line.
- `cli.test.ts`: `--parallel` parsing, updated usage line,
  `OMNISEARCH_PARALLEL` parse + invalid-name error.
- `server.test.ts`: `callTool` with `parallel: true` over
  InMemoryTransport returns merged markdown with the parallel via-label.
- `plugin-impl.test.ts`: `execute({ query, parallel: true })` passthrough.

## 7. Risks

- Provider wire formats drift (Tavily/Google/Perplexity fields) — mitigated
  by isolating parsing per provider file and mock tests documenting the
  exact shapes we rely on.
- SearXNG JSON format disabled by default on self-hosted instances — the
  403 error message names the fix.
- Google quota exhaustion (100/day free) — 10/60s default limiter and the
  combined-error message surface it cleanly.
