# Omnisearch v1.2 — Reliability & Production Readiness (Design)

Date: 2026-09-02
Status: Approved (grill-with-docs interview 2026-09-02; decisions recorded in ADRs 0001–0007)
Branch: `feat/v1.2-reliability` (to fork from `main` after the ADR commits)
Release: **0.3.0**, minor, no breaking changes

## Context

v1.1 (0.2.0) ships 8 providers, parallel fan-out with round-robin merge,
fallback chains, LRU+TTL cache, per-provider token-bucket rate limiting, an
MCP stdio server, a CLI, and two native plugins. Two verified defects
undermine it in production: **no request timeouts** (a hung provider stalls a
chain or fan-out indefinitely — `fetch` has no default timeout) and **no
CI**. Provider output is also interpolated into markdown unescaped (parked
review finding), and nothing is published to npm despite the README's
`npx` promise.

This release makes the system production-ready: timeouts, retries, CI,
escaping, and full npm publication prep. All decisions were settled in the
design interview and are recorded as ADRs — this spec argues from them:

| ADR | Decision |
|---|---|
| [0001](../../decisions/ADR-0001-v1.2-scope-reliability-first.md) | v1.2 = reliability first, npm polish, minor release |
| [0002](../../decisions/ADR-0002-dependency-policy.md) | zero new dependencies; exceptions need their own ADR |
| [0003](../../decisions/ADR-0003-request-timeouts.md) | global 30s timeout via `OMNISEARCH_TIMEOUT_MS` |
| [0004](../../decisions/ADR-0004-retry-with-backoff.md) | 2 in-provider retries on transient failures, backoff + jitter |
| [0005](../../decisions/ADR-0005-ci-github-actions.md) | CI: GitHub Actions, ubuntu + windows, bun 1.x |
| [0006](../../decisions/ADR-0006-npm-publication.md) | all 4 packages; maintainer runs the final publish |
| [0007](../../decisions/ADR-0007-markdown-escaping.md) | escape markdown-significant chars in titles only |

## 1. Timeout plumbing (ADR-0003)

- `OMNISEARCH_TIMEOUT_MS`: positive integer env var, parsed by
  `routerConfigFromEnv` with the existing `positiveIntFromEnv` validation,
  default **30000**. Lands in `RouterConfig.timeoutMs`.
- **Signal propagation**: `SearchOptions` gains `signal?: AbortSignal`
  (router-injected; deliberately not exposed in the tool schema). The
  router constructs `AbortSignal.timeout(config.timeoutMs)` fresh per
  attempt and passes it down.
- Every provider honors it:
  - fetch-based providers (brave, tavily, google, searxng) pass `signal`
    to `fetch`.
  - SDK providers (anthropic, openai, moonshot, perplexity) pass `{ signal }`
    as the SDK request-options argument (both the Anthropic and OpenAI
    SDKs accept a per-call `signal`).
- A timed-out call is classified **transient** (§2), so it retries and then
  falls through the chain normally.

## 2. Retry with backoff (ADR-0004)

- Fixed `MAX_RETRIES = 2` (3 attempts total); **not** env-configurable
  (interview decision — fewest knobs).
- **Transient classifier** `isTransientSearchError(error)` (new, in
  `router.ts`): true for HTTP 5xx and 429 (matched against the providers'
  standardized `... search failed: HTTP <status>` message shape), network
  failures (`fetch failed` TypeErrors, `ECONNRESET`/`ETIMEDOUT`/`ECONNREFUSED`
  causes), and timeout/abort errors (`TimeoutError`, `AbortError`, and the
  message from our own timeout wrapper). Everything else (4xx auth/quota
  errors, config errors) is permanent.
- Retry lives **inside the router's attempt loop**: on a transient failure
  with attempts remaining, wait `500 * 2^(attempt-1) + jitter(0..250)` ms,
  **re-acquire the provider's rate-limit token** (no limiter bypass), and
  call the same provider again. After the final attempt (or a permanent
  error), the existing chain/fan-out behavior proceeds unchanged.
- Parallel mode retries per participant inside its own task — a flapping
  participant does not fail the whole fan-out.
- Testability: `RouterConfig` gains an optional `sleepImpl` injection
  (defaults to real `setTimeout`); retry tests assert backoff durations
  and attempt counts via recorded sleeps.

## 3. Markdown escaping (ADR-0007)

- `normalize.ts` gains `escapeMarkdownTitle(title)` replacing `[`, `]`,
  `(`, `)` with backslash-escaped forms, applied to titles in
  `normalizeResults` numbered links. URLs and snippets are untouched.
- Malformed titles can no longer break the response's markdown structure.

## 4. CI (ADR-0005)

- `.github/workflows/ci.yml`: `on: push/ pull_request` to `main`; matrix
  `[ubuntu-latest, windows-latest]`; bun via `oven-sh/setup-bun` pinned to
  `1.x`; steps: `bun install --frozen-lockfile` → `bun test` →
  `bun run typecheck` → `bun run build`.
- CI is declarative — validated by YAML syntax checks and the first real
  push, not by local execution.

## 5. npm publication prep (ADR-0006)

- Per-package `README.md` (short: what it is, pointer to the repo root)
  for `shared`, `opencode-plugin`, `kilocode-plugin` (mcp-server already
  documents itself in the root README — it gets the full one copied at
  publish-prep time or references the repo).
- `@omnisearch/shared`: inspect the emitted `.d.ts` for direct zod
  imports; if unreferenced, drop the `zod` dependency (interview decision:
  verify-then-remove; if referenced, keep and note why in the checklist).
- Validate with `bun publish --dry-run` per package in dependency order
  (shared → mcp-server → opencode-plugin → kilocode-plugin).
- `docs/publish-checklist.md`: exact maintainer commands, npm org
  prerequisites (create `@omnisearch` org, public access), and the
  reminder that `workspace:*` requires `bun publish` (not npm publish).

## 6. Versions

All five package.json files → **0.3.0**; lockfile refreshed.

## Testing strategy (TDD throughout)

- **Timeouts**: provider tests assert the signal is forwarded to fetch/SDK
  calls; a router test asserts `SearchOptions.signal` is an aborted-capable
  `AbortSignal` with the configured timeout; env parsing tests for
  `OMNISEARCH_TIMEOUT_MS` (default 30000, non-numeric rejected).
- **Retries**: classifier unit tests (each transient class, each permanent
  class); router tests — transient-then-success returns results with the
  provider called 3 times and 2 limiter acquisitions beyond the first;
  permanent 4xx makes zero retries; backoff sleeps recorded via injected
  `sleepImpl`; parallel participant retry keeps other participants'
  results intact.
- **Escaping**: normalizer tests for bracket/paren titles, mixed content,
  URL and snippet passthrough.
- **Publish prep**: `bun publish --dry-run` per package (commands, not
  unit tests); d.ts zod-reference check is a documented verification step.
- Full-suite green after every task; built-bin probes at the end.

## Non-goals (v1.3+ candidates, from the interview)

`omnisearch doctor` diagnostics, `omnisearch_fetch` page-reader tool,
domain include/exclude + date-range filters, per-call participant lists,
DuckDuckGo zero-key provider, budget guards, streaming, persistent cache,
score-aware merging.

## Risks

- Error-message-based transient classification couples the router to the
  providers' standardized message shape — acceptable: the shape is
  enforced by this repo's own provider suite and asserted in classifier
  tests; if a provider format drifts, its tests fail first.
- SDK per-call `signal` support differences (anthropic/openai SDKs) —
  verified against installed SDK versions during implementation; both
  document `signal` in request options.
- GHA Windows runners and `bun run` script chaining (`&&`) — cmd-compatible;
  first CI run will confirm.
