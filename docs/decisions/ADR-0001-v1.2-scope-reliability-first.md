# ADR-0001: v1.2 scope — reliability first, polished for npm, minor release

Date: 2026-09-02
Status: Accepted

## Context

Omnisearch v1.1 (0.2.0) ships 8 providers, parallel fan-out, fallback chains,
caching, rate limiting, an MCP server, a CLI, and two native plugins. Four
feature axes were candidates for the next release: agent power (fetch tool,
filters), reliability, provider breadth, and cost control. Two verified
reliability defects exist today: no fetch timeouts anywhere (a hung provider
stalls a fallback chain or parallel fan-out indefinitely) and no CI gating
merges.

## Decision

The next release is **v1.2 (0.3.0), a minor release** scoped to
**reliability and production readiness**:

1. Per-request timeouts on every provider call (fetch + SDK paths).
2. Retry with backoff for transient failures, composed with the existing
   rate limiter and fallback chain.
3. GitHub Actions CI (test + typecheck + build) gating `main`.
4. Markdown escaping of provider titles in normalized output.
5. npm publication readiness for all four packages.

Audience: omnisearch is polished **for npm publication** (npx-first
onboarding, semver discipline), not just personal use. Remaining axes
(agent power first) chain as v1.3+ rather than bundling into a v2.0.

## Consequences

- A hung provider can no longer stall a search indefinitely.
- Every merge is gated by CI on the platforms the project actually runs on.
- Publication becomes a credential-only step (maintainer runs the final
  publish command).
- Agent-power features (fetch tool, filters) are explicitly deferred to the
  next release, not silently dropped.
